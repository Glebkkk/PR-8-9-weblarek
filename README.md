# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

### `TPayment`

Тип описывает доступные способы оплаты заказа.

```ts
type TPayment = 'card' | 'cash';
```

Значения:  
`card` — оплата онлайн.  
`cash` — оплата при получении.


### `IProduct`

Интерфейс описывает товар, который приходит с сервера и используется в каталоге, карточке подробного просмотра и корзине.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Поля интерфейса:  
`id: string` — уникальный идентификатор товара.  
`description: string` — подробное описание товара.  
`image: string` — путь к изображению товара.  
`title: string` — название товара.  
`category: string` — категория товара.  
`price: number | null` — цена товара. Если значение равно `null`, товар недоступен для покупки.


### `IBuyer`

Интерфейс описывает данные покупателя, которые пользователь вводит при оформлении заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Поля интерфейса:  
`payment: TPayment` — выбранный способ оплаты.  
`email: string` — электронная почта покупателя.  
`phone: string` — телефон покупателя.  
`address: string` — адрес доставки.


### `IBuyerErrors`

Интерфейс описывает объект с ошибками валидации данных покупателя. Если поле заполнено корректно, соответствующее свойство в объекте отсутствует.

```ts
interface IBuyerErrors {
  payment?: string;
  email?: string;
  phone?: string;
  address?: string;
}
```

Поля интерфейса:  
`payment?: string` — текст ошибки, если не выбран способ оплаты.  
`email?: string` — текст ошибки, если не указана электронная почта.  
`phone?: string` — текст ошибки, если не указан телефон.  
`address?: string` — текст ошибки, если не указан адрес доставки.


### `IProductsResponse`

Интерфейс описывает объект, который сервер возвращает при запросе каталога товаров.

```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

Поля интерфейса:  
`total: number` — общее количество товаров в каталоге.  
`items: IProduct[]` — массив товаров, полученных с сервера.


### `IOrder`

Интерфейс описывает объект заказа, который отправляется на сервер при оформлении покупки. Расширяет `IBuyer`, поэтому содержит данные покупателя и дополнительные данные заказа.

```ts
interface IOrder extends IBuyer {
  total: number;
  items: string[];
}
```

Поля интерфейса:  
`payment: TPayment` — выбранный способ оплаты.  
`email: string` — электронная почта покупателя.  
`phone: string` — телефон покупателя.  
`address: string` — адрес доставки.  
`total: number` — общая стоимость товаров в заказе.  
`items: string[]` — массив идентификаторов товаров, выбранных покупателем.


### `IOrderResult`

Интерфейс описывает объект, который сервер возвращает после успешного оформления заказа.

```ts
interface IOrderResult {
  id: string;
  total: number;
}
```

Поля интерфейса:  
`id: string` — идентификатор оформленного заказа.  
`total: number` — итоговая сумма заказа.


## Модели данных

### `ProductCatalog`

Класс отвечает за хранение товаров, полученных с сервера, и за хранение товара, выбранного пользователем для подробного просмотра.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`items: IProduct[]` — массив всех товаров каталога.  
`preview: IProduct | null` — товар, выбранный для подробного отображения.

Методы класса:  
`setItems(items: IProduct[]): void` — сохраняет массив товаров в модель.  
`getItems(): IProduct[]` — возвращает массив товаров.  
`getProduct(id: string): IProduct | undefined` — возвращает товар по его идентификатору.  
`setPreview(product: IProduct): void` — сохраняет товар для подробного просмотра.  
`getPreview(): IProduct | null` — возвращает выбранный товар.

События:  
`items:change` — изменился список товаров каталога. В данных события `{ items: IProduct[] }`.  
`preview:change` — изменился товар для подробного просмотра. В данных события `{ preview: IProduct | null }`.


### `BasketModel`

Класс отвечает за хранение товаров, которые пользователь добавил в корзину, и за вычисление данных, связанных с корзиной.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`items: IProduct[]` — массив товаров, добавленных в корзину.

Методы класса:  
`getItems(): IProduct[]` — возвращает массив товаров корзины.  
`addItem(product: IProduct): void` — добавляет товар в корзину.  
`removeItem(id: string): void` — удаляет товар из корзины по идентификатору.  
`clear(): void` — очищает корзину.  
`getTotal(): number` — возвращает общую стоимость товаров в корзине.  
`getCount(): number` — возвращает количество товаров в корзине.  
`hasItem(id: string): boolean` — проверяет наличие товара в корзине по идентификатору.

События:  
`basket:change` — изменилось содержимое корзины. В данных события `{ items: IProduct[] }`.


### `OrderModel`

Класс отвечает за хранение данных покупателя, которые пользователь указывает при оформлении заказа, и за их валидацию.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`payment: TPayment | null` — выбранный способ оплаты. Значение `null` означает, что способ оплаты ещё не выбран.  
`address: string` — адрес доставки.  
`email: string` — электронная почта покупателя.  
`phone: string` — телефон покупателя.

Методы класса:  
`setData(data: Partial<IBuyer>): void` — сохраняет одно или несколько полей покупателя, не очищая остальные данные.  
`getData(): IBuyer | null` — возвращает данные покупателя или `null`, если способ оплаты не выбран.  
`clear(): void` — очищает данные покупателя.  
`validate(): IBuyerErrors` — возвращает объект с ошибками валидации. Если объект пустой, данные покупателя валидны.

События:  
`buyer:change` — изменились данные покупателя. В данных события `{ data: IBuyer | null }`.

## Слой коммуникации

### `LarekApi`

Класс отвечает за получение данных о товарах с сервера и отправку заказа на сервер. Класс использует композицию: принимает в конструктор объект, соответствующий интерфейсу `IApi`, и вызывает его методы `get` и `post`.

Типы:
IProductsResponse — ответ сервера с каталогом;
IOrder — объект заказа для отправки;
IOrderResult — ответ сервера после оформления заказа.

Конструктор:
`constructor(api: IApi)` - принимает объект для выполнения HTTP-запросов.

Поля класса:
`api: IApi` - объект, через который выполняются запросы к серверу.

Методы класса:
`getProducts(): Promise<IProductsResponse>` - выполняет GET-запрос на эндпоинт `/product/` и возвращает объект с массивом товаров.
`createOrder(order: IOrder): Promise<IOrderResult>` - выполняет POST-запрос на эндпоинт `/order/`, отправляет данные заказа и возвращает результат оформления заказа.

## Слой представления

Слой представления отвечает за отображение данных на странице и за генерацию событий в ответ на действия пользователя. Компоненты представления не изменяют модели напрямую. Все пользовательские действия передаются в презентер через брокер событий.


### `Page`

Класс отвечает за основные элементы страницы: каталог товаров, счетчик товаров в корзине и состояние блокировки страницы при открытии модального окна.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент страницы и брокер событий.

Поля класса:
`wrapper: HTMLElement` - обертка страницы, на которую добавляется класс блокировки при открытии модального окна.
`basketButton: HTMLButtonElement` - кнопка открытия корзины в шапке.
`counter: HTMLElement` - элемент счетчика товаров в корзине.
`gallery: HTMLElement` - контейнер каталога товаров.

Методы и сеттеры класса:
`set counter(value: number)` - обновляет значение счетчика товаров в корзине.
`set catalog(items: HTMLElement[])` — отображает карточки товаров в каталоге.
`set locked(value: boolean)` — блокирует или разблокирует страницу при открытии и закрытии модального окна.

События:
`basket:open` — пользователь нажал на кнопку корзины.

### `Modal`

Класс отвечает за модальное окно: открывает и закрывает его, а также отображает внутри переданное содержимое.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает контейнер модального окна и брокер событий.

Поля класса:
`content: HTMLElement` - контейнер, в который вставляется компонент для отображения в модальном окне.
`closeButton: HTMLButtonElement` - кнопка, закрывающая модальное окно.

Методы и сеттеры класса:
`set content(value: HTMLElement)` - отображает переданный контент в модальном окне.
`open(): void` — открывает модальное окно.
`close(): void` — закрывает модальное окно и очищает его содержимое.
`render(data: { content: HTMLElement }): HTMLElement` — отображает модальное окно с переданным содержимым.

События:  
`modal:close` — пользователь закрыл модальное окно.
`modal:open` — модальное окно открыто.


### `Card`

Базовый класс карточки товара. Содержит общую логику для карточки в каталоге, карточки подробного просмотра и карточки товара в корзине.

Поля класса:  
`id: string` — идентификатор товара.  
`title: HTMLElement` — название товара.  
`price: HTMLElement` — цена товара.

Методы и сеттеры класса:  
`set id(value: string)` — сохраняет идентификатор товара.  
`set title(value: string)` — отображает название товара.  
`set price(value: number | null)` — отображает цену товара или текст о недоступности товара.


### `CatalogCard`

Класс отвечает за отображение карточки товара в каталоге.

Наследование: 
`CatalogCard` наследуется от `Card`.

Поля класса:
`category: HTMLElement` - категория товара.
`image: HTMLImageElement` - изображение товара.

Методы и сеттеры класса:
`set category(value: string)` - отображает категорию товара и устанавливает класс модификатора категории.
`set image(value: string)` - отображает изображение товара.

События:
`card:select` — пользователь нажал на карточку товара в каталоге.

### `PreviewCard`

Класс отвечает за отображение карточки подробного просмотра в модальном окне.

Наследование:
`PreviewCard` наследуется от `Card`.

Поля класса:
`category: HTMLElement` - категория товара.
`image: HTMLImageElement` - изображение товара.
`description: HTMLElement` - описание товара.
`button: HTMLButtonElement` — кнопка добавления товара в корзину.

Методы и сеттеры класса:
`set category(value: string)` - отображает категорию товара и устанавливает класс модификатора категории.
`set image(value: string)` - отображает изображение товара.
`set description(value: string)` - отображает описание товара.
`set inBasket(value: boolean)` - изменяет текст или состояние кнопки в зависимости от наличия товара в корзине.


События:
`basket:add` - пользователь нажал на кнопку добавления товара в корзину.

### `BasketCard`

Класс отвечает за отображение карточки в корзине.

Наследование:  
`BasketCard` наследуется от `Card`.

Поля класса:
`index: HTMLElement` - порядковый номер товара в корзине.
`deleteButton: HTMLButtonElement` - кнопка удаления товара из корзины.

Методы и сеттеры класса:
`set index(value: number)` - отображает порядковый номер товара в корзине.

События:
`basket:remove` - пользователь нажал на кнопку удаления товара из корзины.

### `Basket`

Класс отвечает за отображение корзины: списка товаров, итоговой стоимости и кнопки перехода к оформлению заказа.

Поля класса:

`list: HTMLElement` - список товаров корзины.
`button: HTMLButtonElement` - кнопка перехода к оформлению заказа.
`price: HTMLElement` - итоговая стоимость товаров.

Методы и сеттеры класса:
`set items(items: HTMLElement[])` — отображает список карточек товаров в корзине. 
`set total(value: number)` — отображает итоговую стоимость товаров. 
`set valid(value: boolean)` — включает или отключает кнопку оформления заказа.

События: 
`order:open` — пользователь нажал кнопку оформления заказа.

### `Form`

Базовый класс, который отвечает за общую логику отображения форм.

Поля:
`submitButton: HTMLButtonElement` — кнопка отправки формы.  
`errors: HTMLElement` — элемент для отображения ошибок формы.

Методы и сеттеры класса:
`onInputChange(field: string, value: string): void` — генерирует событие изменения поля формы.

## Презентер

Презентер связывает слои Model и View. В приложении одна страница, поэтому логика презентера реализована в файле `src/main.ts` — отдельный класс не используется.

Презентер не хранит данные и не генерирует события. Он подписывается на события моделей и представлений и выполняет действия: вызывает методы моделей для изменения данных или обновляет компоненты представления.

Обновление представления выполняется только в двух случаях:
- при получении события об изменении данных от модели (`items:change`, `preview:change`, `basket:change`, `buyer:change`);
- при открытии модального окна — отображение содержимого модалки (превью, корзина, формы, успешный заказ) и блокировка страницы по событию `modal:open`.

### Обработка событий моделей

| Событие | Действие презентера |
|---------|---------------------|
| `items:change` | Получить товары из каталога, создать карточки `CatalogCard`, передать их в `Page` |
| `preview:change` | Отобразить `PreviewCard` в модальном окне |
| `basket:change` | Обновить счётчик в шапке; при открытой корзине или превью — перерисовать их содержимое |
| `buyer:change` | Перерисовать открытую форму заказа или контактов |

### Обработка событий представления

| Событие | Действие презентера |
|---------|---------------------|
| `card:select` | Сохранить выбранный товар в модели каталога (`setPreview`) |
| `basket:add` | Добавить товар в корзину |
| `basket:remove` | Удалить товар из корзины |
| `basket:open` | Отобразить корзину в модальном окне |
| `order:open` | Отобразить форму первого шага заказа |
| `order:change` | Сохранить данные первого шага в `OrderModel` |
| `order:submit` | При валидных данных открыть форму контактов, иначе показать ошибки |
| `contacts:change` | Сохранить контактные данные в `OrderModel` |
| `contacts:submit` | Отправить заказ на сервер, очистить корзину и данные покупателя, показать успех |
| `success:close` | Закрыть модальное окно |
| `modal:open` | Заблокировать прокрутку страницы |
| `modal:close` | Разблокировать страницу |

## События приложения

### События моделей данных

`items:change` — изменился список товаров каталога. Данные: `{ items: IProduct[] }`.

`preview:change` — изменился товар для подробного просмотра. Данные: `{ preview: IProduct | null }`.

`basket:change` — изменилось содержимое корзины. Данные: `{ items: IProduct[] }`.

`buyer:change` — изменились данные покупателя. Данные: `{ data: IBuyer | null }`.

### События представления

`basket:open` — пользователь нажал на кнопку корзины в шапке сайта.

`modal:open` — модальное окно открыто.

`modal:close` — пользователь закрыл модальное окно (кнопка закрытия).

`card:select` — пользователь нажал на карточку товара в каталоге. В данных события передаётся `{ id: string }` — идентификатор товара.

`basket:add` — пользователь нажал кнопку «В корзину» в карточке подробного просмотра. В данных события передаётся `{ id: string }` — идентификатор товара.

`basket:remove` — пользователь нажал кнопку удаления товара в корзине. В данных события передаётся `{ id: string }` — идентификатор товара.

`order:open` — пользователь нажал кнопку «Оформить» в корзине.

`form:change` — пользователь изменил поле формы. В данных события передаётся `{ field: string, value: string }` — имя поля и новое значение.

`form:submit` — пользователь отправил форму.

`order:change` — пользователь изменил данные первого шага оформления заказа (способ оплаты или адрес).

`order:submit` — пользователь отправил первый шаг оформления заказа.

`contacts:change` — пользователь изменил данные второго шага оформления заказа (email или телефон).

`contacts:submit` — пользователь отправил второй шаг оформления заказа.

`success:close` — пользователь нажал кнопку закрытия сообщения об успешном оформлении заказа.
